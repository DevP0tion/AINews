### Google, Workspace AI 에이전트의 MCP 서버 경유를 의무화
Google이 11월 24일 Workspace MCP 서버 8종을 정식 출시(GA)하고 API 약관을 개정해, 2027년 2월 1일부터 AI 에이전트이거나 에이전트가 구동하는 도구는 Gmail·Drive·Calendar 등 Workspace 서비스에 반드시 이 MCP 서버를 통해 접근해야 한다고 명시했다. 같은 시점부터 REST API를 직접 호출하는 에이전트는 유료 등급과 무관하게 Standard 등급 쿼터만 받으며, 백업·동기화 같은 비(非)AI 앱은 영향을 받지 않는다. 다만 공개된 Gmail MCP 서버는 스레드 검색·읽기와 초안 생성·라벨 관리까지만 가능하고 메일 발송·회신·전달은 'partner access' 필요로 분류돼 일반 제공되지 않는다.

### "OpenAI가 비용 절감 모드에 들어간 듯하다" — Astra/Sol 6.2의 추론 토큰 급감 분석
모델 대결형 평가 시스템 Agent Duel을 운영하는 블로거가, 같은 과제를 두고 비교했을 때 Astra 6.2와 Sol 6.2가 직전 세대보다 추론 토큰과 출력 토큰을 눈에 띄게 적게 쓴다는 데이터를 공개했다. 100표 이상을 받은 18개 모델의 중간값 기준으로 추론 토큰 감소의 p값은 Sol 0.00013·Astra 0.0064, 출력 토큰 감소는 Sol 0.0055·Astra 0.022였다. 저자는 이를 두 모델이 '비용 튜닝'된 결과로 해석하며 혹평의 원인으로 추정하지만, OpenAI의 의도를 보여주는 근거는 제시되지 않은 저자 개인의 추론이다.
[원문](https://micjm.com/blog/openai-is-in-cost-control-mode/)

### Mixture-of-Loops Transformer — KV를 루프 간 메모리로 재사용하는 looped Transformer
Looped Transformer가 레이어를 재사용해 표현력을 얻는 대신 효율을 잃는 문제를 두고, 저자들은 '루프 사이에 무엇을 넘길지'를 다시 설계해 key/value를 깊이·루프를 가로질러 선택적으로 재사용하는 메모리로 쓰는 MoLA 어텐션과 MoLT를 제안했다. residual stream을 유지하는 MoLT-R과 임베딩에서 다시 시작해 이전 루프의 메모리 KV를 섞는 MoLT-KV로 표현력·효율을 나눴고, 후자는 loop forcing과 결합해 학습 루프 수를 넘는 단일 패스 디코딩이 가능하다. 400B 토큰 사전학습에서 700M 모델은 OLMo3 대비 검증 cross-entropy 토큰 효율 1.7배, 3B MoE는 10개 도메인 perplexity 0.75 감소·10개 과제 정확도 2.1%p 상승을 보고했다.
[원문](https://arxiv.org/abs/2611.34923v1)
